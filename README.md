# AI 历史人物模拟器（Demo）

一个教育场景的 AI 应用原型：**AI 扮演"有立场、可能带偏见的历史人物"**，
学生在对话中追问、质疑，再对照史料自己去判断——训练的是「历史思维」，
而不是「记住史实」。

## 快速开始（零依赖）

需要 Python ≥ 3.11，**无需安装任何第三方包**：

```bash
cd new-chat
python3 -m src.app.server
```

然后打开浏览器：**http://127.0.0.1:8777**

- 学生端：`/`
- 教师端：`/teacher`

## 功能

### 学生端
- 首页展示已发布的历史人物卡片（默认 3 位：诸葛亮、苏格拉底、林肯），每人一张手绘卡通形象。
- 点击卡片 → 进入**对话子页面**：干净清爽的对话框。
- 对话框下方可选择 **API 接口**（离线演示 / OpenAI 兼容 / 本地 Ollama / Anthropic Claude），
  可填模型名、Base URL、API Key（**密钥只存在你自己浏览器的 localStorage，不上传服务器**）。
- 「＋ 新对话」重置会话。
- **右侧「资料与任务」是可折叠抽屉**（默认收起，保持纯粹的对话界面）：里面有抉择任务、我的历史思维画像、可查证史料、建议问题与提示。宽屏时抽屉占右侧 340px、对话仍可见；窄屏时改为全屏覆盖，**不会再把对话挤到下面**。
- **API 设置默认收成一行**（`API：<接口> · <模型>`），点 ⚙️ 才展开模型 / Base URL / Key。

### 教师端
- 与学生端相同的对话能力（可点「以学生身份测试」）。
- 管理历史人物：**新建 / 修改 / 删除 / 发布**。
- **按板块分标签页编辑**，不再把所有内容挤在一个大表单里：

  | 板块 | 内容 |
  | --- | --- |
  | 基本信息 | ID、姓名、时代、难度、主题色（取色器）、简介、形象路径 |
  | 人物设定 | 开场白 + **限制词 / system prompt**（AI 行为约束） |
  | 史料 | **每份史料一张卡片**，可单独增删改；类型用下拉菜单，含「自定义」 |
  | 建议问题 | 逐条增删改 |
  | 抉择节点 | 每个抉择一张卡片：情境 + 提示 + **可逐条增删的选项** |
  | 发布 | 是否发布给学生端 |

- 标签上有数量徽标（史料 / 问题 / 抉择各几条），一眼可见。
- **形象支持拖拽上传**：把图片拖进虚线框（或点击选择）即可，支持 PNG / JPG / WEBP / GIF，单张 ≤ 2 MB；也保留路径输入框可手动填写。上传文件落在 `web/assets/avatars/uploads/`（已加入 .gitignore）。
- **列表可拖拽排序**：史料、建议问题、抉择节点、抉择选项都能按住左侧 ⠿ 手柄拖动。
- **未保存提醒**：有改动时标题旁显示 ● 未保存；切换人物 / 新建 / 关闭页面都会先确认。
- 「保存并发布」后，学生端立即生效。

### 抉择任务（P0-1）
不止自由对话——每位历史人物自带若干**「历史抉择节点」**：

1. 学生阅读情境 → 从选项中**做出选择** → 写下**书面论证**（要求引用史料）。
2. 系统按**历史思维量表**给出反馈：

   | 维度 | 说明 |
   | --- | --- |
   | 史料溯源 sourcing | 是否追问或标注信息来源与立场 |
   | 语境化 contextualization | 是否把决策放回时代背景 |
   | 交叉验证 corroboration | 是否对照多个来源 |
   | 论证 argumentation | 是否有「论点—证据—推理」 |
   | 历史共情 historical_empathy | 是否理解当时人的处境 |

   每项 0–3 分，附「做得好 / 可改进 / 点评」。

- 入口：对话页右侧「抉择任务」面板。
- 教师端可编辑抉择节点（文本格式，见教师端表单说明）。
- 提交记录存于 `data/submissions.json`。

### 史料交叉验证（P0-2）
1. 每条 AI 回复下方有 **「🔍 核对史料」** 按钮。
2. 点开后：显示**要核对的说法** + 该人物的**史料清单（含原文摘要）**。
3. 学生判断这条说法：**相符 / 有出入 / 史料未涉及**，并写出**依据**（引用哪份史料、为什么）。
4. 系统作为「史料裁判」给出反馈：判断是否站得住 + 改进建议 + 参照判断。
- 记录存于 `data/checks.json`。

### 评分深化与学情分析（P0-3）
- **双评分 + 一致性**：抉择论证可开启「双评分」——用两次独立评分取均值，并给出逐维**一致性（高/中/低）**；一致性偏低时提示需人工复核。这是对**评分信度**的处理。
- **学生端「我的历史思维画像」**：累计该学生在抉择任务中各维度的平均表现，并指出最需加强的维度。
- **教师端「学情分析」**（`/analytics`）：
  - 抉择提交数 / 史料核对数 / 人物数 / 全体最弱维度
  - 全体历史思维各维度平均（条形）
  - 最近提交记录（人物、抉择、选择、论证摘要、得分）

### 教学法强化（P0-4）
- **自评对比**：提交抉择论证前，学生先按 5 维 rubric 给自己打 0–3 分（**必填**）；结果页并列显示「自评 vs AI」逐维差距，并给出整体高估/低估倾向。→ 元认知
- **分级支架**：抉择提示默认隐藏，点击逐级揭示（最多 3 级，始终不给答案）；记录使用级数、**不扣分**，反馈与学情中可见。→ 生产性失败 / 合意困难
- **快捷追问**：对话框上方固定 4 个元问题按钮（你的依据是什么 / 还有别的说法吗 / 当时的人会怎么看 / 你确定吗），点击**填入输入框**（不自动发送）。→ sourcing
- **核对并入画像**：史料核对也产出 sourcing / corroboration / argumentation 三个维度分，与抉择得分**合并成一份画像**；学情分析页新增「平均提示级数」与「自评偏差」。→ corroboration

> 注：抉择数据由 `hint` 迁移为 `hints`（最多 3 级），`SEED_VERSION` 已提升，`data/figures.json` 会按 seed 重建。

### 指标说明与水平划分（P0-5）
指标是专业术语，光给分数学生看不懂，所以补了一层"看得懂"的解释：

- `GET /api/rubric` 是**单一定义源**：5 个维度的**含义**与**低/高表现**，以及 **4 档水平分段**：

  | 水平 | 平均分区间 | 说明 |
  | --- | --- | --- |
  | 起步 | 0 – 0.75 | 还很少体现，需要示范与练习 |
  | 初步 | 0.75 – 1.5 | 偶尔能做到，但不稳定 |
  | 较好 | 1.5 – 2.5 | 多数时候能做到 |
  | 成熟 | 2.5 – 3 | 稳定而自觉地做到 |

- **学情分析页**新增「指标说明与水平划分」面板（水平色带 + 5 张维度卡：含义 / 低表现 / 高表现），画像每条后面带**水平标签**。
- **学生端**「我的历史思维画像」每条也带水平标签，并提供 **「📖 指标说明与水平划分」** 按钮（复用弹窗）。
- **每个指标名旁有一个悬停说明**：鼠标移上去才显示该指标的一句话解释，不移开则保持隐藏（纯 CSS，无 JS 依赖；同时支持键盘 `Tab` 聚焦显示），保证界面简洁。

## 界面多语言（简体中文 / 繁體中文 / English）

右上角有语言切换下拉框，四个页面（学生端 / 对话页 / 教师端 / 学情分析）通用，选择记在 `localStorage`。

**范围**：切换的是**操作界面文案**——导航、按钮、表单标签、提示语、指标名与解释、水平档位。
**不翻译**：教师填写的人物内容（人设、史料、抉择情境），以及 AI 回复与学生自己的答案；
这些区域用 `data-no-i18n` 标记，确保不会被误翻。

**AI 回复语言跟随界面**：切到 English / 繁體時，会在人物 prompt 与评分 prompt 后追加语言约束。

**实现**（`web/assets/i18n.js`）：
- 以**简体原文为键**的词典（200+ 条）+ 句式模式（带数字的动态句）+ 前缀规则（`选择：xxx` 只翻前缀）。
- 用 `WeakMap` 保存原文，切回中文能精确还原。
- `MutationObserver` 自动翻译后渲染出来的内容，因此无需修改现有 180+ 处调用点。
- 指标文案仍来自 `/api/rubric` 单一定义源，前端只负责显示。
- 验证脚本：`node tools/i18n_probe.mjs`（最小 DOM 桩，验证翻译、还原与不误翻）。

### 自定义人物：限制词"开箱即用"（P0-7）

老师通常写不出合格的**人物扮演限制词**，这会直接拉低整个项目的质量。因此「人物设定」页提供三种互补的方式：

1. **⚡ 快速生成（不依赖 AI）**：只填 姓名 / 时代 / 身份 / 主要立场 / 学生扮演 / 回答长度上限 这几格，系统按统一模板补成结构完整的限制词，**必定包含四块**：`身份与立场`、`知识边界`、`作为有立场者`、`教学约束`。纯规则生成，无网、无 Key 也能用。
2. **🤖 交给 AI 增强**：同一份表单再加可选补充资料，交给模型写得更自然。**模型输出缺少任一必需章节时会自动回退到模板**，并在界面注明原因——老师永远不会拿到半成品。
3. **📄 拖入人物设定文档**：支持 `.md / .txt / .docx`（≤ 5MB）。拖入后先出**内容预览**，再选择「填入限制词」直接用，或「✨ 规范成模板」交给 AI 重排成统一结构。

对应接口：`POST /api/persona`（`mode: template|ai`）、`POST /api/extract`。

> 设计取舍：文档只做**前端可见的预览与二次确认**，不直接静默覆盖限制词；AI 失败一律降级到模板，不让老师卡住。

## API 接口选项

| 接口 | 说明 | 需要 Key |
| --- | --- | --- |
| 离线演示 | 不调用任何模型，返回模拟回复，方便无网演示 | 否 |
| OpenAI 兼容 | OpenAI / DeepSeek / 通义 / 智谱 等，填对应 Base URL 与模型名 | 是 |

## 说明与边界

- **不训练模型**：本项目是「自研前端 + 预训练模型接口 + 提示工程」。
- 人物卡通形象为**手工 SVG**（可替换）。
- 对话数据目前**不落库**，刷新页面即清空；人物配置存于 `data/figures.json`。
- 历史人物为**教学模拟**，允许展现立场与时代局限，不代表史实定论。

## 分享给别人

### 场景一：同一局域网（最快，适合答辩现场 / 同学围观）

```bash
python3 -m src.app.server --host 0.0.0.0
```

启动后会打印一条形如 `http://192.168.x.x:8777` 的地址，**发给同一 WiFi 下的任何设备**（手机、平板、别人的电脑）都能打开，无需装任何东西。

> macOS 首次可能弹窗询问"是否允许 Python 接受传入网络连接"，要点**允许**。
> 关闭终端即停止服务。

### 场景二：只给队友看代码

仓库是私有的，到 **GitHub → Settings → Collaborators** 里把队友加进来即可。

### 场景三：让任何人点开链接就能用（需要部署）

本项目是**零依赖**的 Python 标准库服务 + 静态前端，可以直接部署到任意支持 Python 的托管平台（Render / Railway / Fly.io 等）：

- 启动命令：`python3 -m src.app.server --host 0.0.0.0 --port $PORT`
- **不需要在服务器上配置任何 API Key**：模型密钥由使用者在页面上自行填写，只存在他本人的浏览器里；不填也能用「离线演示」模式。
- 也可以先录一段演示视频，作为备选。

## Bug 修复日志

> 最新修复在最上面。组员拉取代码后若问题仍在，请先**重启服务**（改过 Python）并**强制刷新浏览器**（`Cmd + Shift + R`）。

### 2026-10-29 · 新建人物保存成功，但学生端看不到（已修复）

**现象**：在教师端新建并保存一个人物，学生端首页始终不出现。

**原因（两个叠加）**
1. 新建人物默认 `published: false`，而学生端列表只返回已发布人物 → **保存成功但不可见**（主因）；
2. `GET /api/figures/<id>` 未做 URL 解码，人物 ID 含中文或空格时点进去直接 **404**。

**修复内容**
- 新建人物默认**已发布**，并在「已发布」勾选框下提示：不勾选学生端看不到；
- `GET` / `DELETE /api/figures/<id>` 增加 `unquote()` 解码；
- JSON 响应加 `Cache-Control: no-store`，避免人物列表被浏览器缓存成旧数据；
- 新增 `tests/test_figure_flow.py`（4 项回归测试：已发布可见 / 未发布隐藏 / 中文 id 可解析 / 未知 id 404）。

**你已经建过的人物怎么办**
打开该人物 → 勾选 **「已发布（学生端可见）」** → 再点一次 **保存并发布**。
（本次修复只影响**新建**的人物，不会自动把旧的草稿变成已发布。）

**验证步骤**
```bash
python3 -m src.app.server      # 重启
```
浏览器强刷后 → 教师端新建一个人物 → 学生端首页应立即可见。

## 常见问题（Troubleshooting）

### 1. `SSL: CERTIFICATE_VERIFY_FAILED` / `unable to get local issuer certificate`
**原因**：python.org 版 Python 在 macOS 上没有安装根证书（默认 cafile 为空）。
程序现已**自动使用系统证书包** `/etc/ssl/cert.pem`，通常无需处理。
若仍报错：
- 运行一次 `/Applications/Python 3.14/Install Certificates.command`；或
- 启动时指定：`SSL_CERT_FILE=/etc/ssl/cert.pem python3 -m src.app.server`

### 2. `Base URL 必须以 http:// 或 https:// 开头`
Base URL 填错了，必须是完整网址：
- DeepSeek：`https://api.deepseek.com`（或 `https://api.deepseek.com/v1`）
- OpenAI：`https://api.openai.com/v1`
- 本地 Ollama：`http://localhost:11434/v1`

### 3. `HTTP 400` / `model not found`
模型名不对。常见正确值：
- DeepSeek：`deepseek-chat` 或 `deepseek-reasoner`
  （**不是**「DeepSeek v4 Flash」这类应用内模型名）
- OpenAI：官方模型 id，如 `gpt-4o-mini`
- Ollama：本机 `ollama list` 里的名字，如 `qwen2.5:7b`

### 4. `HTTP 401` / Authentication
API Key 无效，或该 Key 没有这个接口的权限。

### 5. 回复一直是模拟内容
检查对话框下方「API 接口」是否还停在「离线演示」。

### 6. 新建了人物，但学生端看不到
按顺序检查：

1. **看发布状态**：教师端人物列表里，该人物右侧应是绿色 **「已发布」**。
   如果显示「未发布」→ 打开它，勾选 **「已发布（学生端可见）」**，再点「保存并发布」。
2. **重启 + 强刷**：改过 Python 必须重启服务；浏览器按 `Cmd + Shift + R`。
3. **人物 ID 别用中文/空格**（虽然 2026-10-29 已修复 URL 解码，但英文 ID 更稳）。
4. 仍不行 → 打开浏览器控制台（F12 → Console），把报错发出来。
