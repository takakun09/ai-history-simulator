# AI 历史人物模拟器（Demo）

一个教育场景的 AI 应用原型：**AI 扮演"有立场、可能带偏见的历史人物"**，
学生在对话中追问、质疑，再对照史料自己去判断——训练的是「历史思维」，
而不是「记住史实」。

## 快速开始（零依赖）

需要 Python ≥ 3.11，**无需安装任何第三方包**：

```bash
cd new-chat
python3 -m src.app.server
```

然后打开浏览器：**http://127.0.0.1:8777**

- 学生端：`/`
- 教师端：`/teacher`

## 功能

### 学生端
- 首页展示已发布的历史人物卡片（默认 3 位：诸葛亮、苏格拉底、林肯），每人一张手绘卡通形象。
- 点击卡片 → 进入**对话子页面**：干净清爽的对话框。
- 对话框下方可选择 **API 接口**（离线演示 / OpenAI 兼容 / 本地 Ollama / Anthropic Claude），
  可填模型名、Base URL、API Key（**密钥只存在你自己浏览器的 localStorage，不上传服务器**）。
- 「＋ 新对话」重置会话；右侧面板列出该人物的**可查证史料**与**建议问题**。

### 教师端
- 与学生端相同的对话能力（可点「以学生身份测试」）。
- 管理历史人物：**新建 / 修改 / 删除 / 发布**。
- **按板块分标签页编辑**，不再把所有内容挤在一个大表单里：

  | 板块 | 内容 |
  | --- | --- |
  | 基本信息 | ID、姓名、时代、难度、主题色（取色器）、简介、形象路径 |
  | 人物设定 | 开场白 + **限制词 / system prompt**（AI 行为约束） |
  | 史料 | **每份史料一张卡片**，可单独增删改；类型用下拉菜单，含「自定义」 |
  | 建议问题 | 逐条增删改 |
  | 抉择节点 | 每个抉择一张卡片：情境 + 提示 + **可逐条增删的选项** |
  | 发布 | 是否发布给学生端 |

- 标签上有数量徽标（史料 / 问题 / 抉择各几条），一眼可见。
- **列表可拖拽排序**：史料、建议问题、抉择节点、抉择选项都能按住左侧 ⠿ 手柄拖动。
- **未保存提醒**：有改动时标题旁显示 ● 未保存；切换人物 / 新建 / 关闭页面都会先确认。
- 「保存并发布」后，学生端立即生效。

### 抉择任务（P0-1）
不止自由对话——每位历史人物自带若干**「历史抉择节点」**：

1. 学生阅读情境 → 从选项中**做出选择** → 写下**书面论证**（要求引用史料）。
2. 系统按**历史思维量表**给出反馈：

   | 维度 | 说明 |
   | --- | --- |
   | 史料溯源 sourcing | 是否追问或标注信息来源与立场 |
   | 语境化 contextualization | 是否把决策放回时代背景 |
   | 交叉验证 corroboration | 是否对照多个来源 |
   | 论证 argumentation | 是否有「论点—证据—推理」 |
   | 历史共情 historical_empathy | 是否理解当时人的处境 |

   每项 0–3 分，附「做得好 / 可改进 / 点评」。

- 入口：对话页右侧「抉择任务」面板。
- 教师端可编辑抉择节点（文本格式，见教师端表单说明）。
- 提交记录存于 `data/submissions.json`。

### 史料交叉验证（P0-2）
1. 每条 AI 回复下方有 **「🔍 核对史料」** 按钮。
2. 点开后：显示**要核对的说法** + 该人物的**史料清单（含原文摘要）**。
3. 学生判断这条说法：**相符 / 有出入 / 史料未涉及**，并写出**依据**（引用哪份史料、为什么）。
4. 系统作为「史料裁判」给出反馈：判断是否站得住 + 改进建议 + 参照判断。
- 记录存于 `data/checks.json`。

### 评分深化与学情分析（P0-3）
- **双评分 + 一致性**：抉择论证可开启「双评分」——用两次独立评分取均值，并给出逐维**一致性（高/中/低）**；一致性偏低时提示需人工复核。这是对**评分信度**的处理。
- **学生端「我的历史思维画像」**：累计该学生在抉择任务中各维度的平均表现，并指出最需加强的维度。
- **教师端「学情分析」**（`/analytics`）：
  - 抉择提交数 / 史料核对数 / 人物数 / 全体最弱维度
  - 全体历史思维各维度平均（条形）
  - 最近提交记录（人物、抉择、选择、论证摘要、得分）

### 教学法强化（P0-4）
- **自评对比**：提交抉择论证前，学生先按 5 维 rubric 给自己打 0–3 分（**必填**）；结果页并列显示「自评 vs AI」逐维差距，并给出整体高估/低估倾向。→ 元认知
- **分级支架**：抉择提示默认隐藏，点击逐级揭示（最多 3 级，始终不给答案）；记录使用级数、**不扣分**，反馈与学情中可见。→ 生产性失败 / 合意困难
- **快捷追问**：对话框上方固定 4 个元问题按钮（你的依据是什么 / 还有别的说法吗 / 当时的人会怎么看 / 你确定吗），点击**填入输入框**（不自动发送）。→ sourcing
- **核对并入画像**：史料核对也产出 sourcing / corroboration / argumentation 三个维度分，与抉择得分**合并成一份画像**；学情分析页新增「平均提示级数」与「自评偏差」。→ corroboration

> 注：抉择数据由 `hint` 迁移为 `hints`（最多 3 级），`SEED_VERSION` 已提升，`data/figures.json` 会按 seed 重建。

### 指标说明与水平划分（P0-5）
指标是专业术语，光给分数学生看不懂，所以补了一层"看得懂"的解释：

- `GET /api/rubric` 是**单一定义源**：5 个维度的**含义**与**低/高表现**，以及 **4 档水平分段**：

  | 水平 | 平均分区间 | 说明 |
  | --- | --- | --- |
  | 起步 | 0 – 0.75 | 还很少体现，需要示范与练习 |
  | 初步 | 0.75 – 1.5 | 偶尔能做到，但不稳定 |
  | 较好 | 1.5 – 2.5 | 多数时候能做到 |
  | 成熟 | 2.5 – 3 | 稳定而自觉地做到 |

- **学情分析页**新增「指标说明与水平划分」面板（水平色带 + 5 张维度卡：含义 / 低表现 / 高表现），画像每条后面带**水平标签**。
- **学生端**「我的历史思维画像」每条也带水平标签，并提供 **「📖 指标说明与水平划分」** 按钮（复用弹窗）。
- **每个指标名旁有一个悬停说明**：鼠标移上去才显示该指标的一句话解释，不移开则保持隐藏（纯 CSS，无 JS 依赖；同时支持键盘 `Tab` 聚焦显示），保证界面简洁。

## API 接口选项

| 接口 | 说明 | 需要 Key |
| --- | --- | --- |
| 离线演示 | 不调用任何模型，返回模拟回复，方便无网演示 | 否 |
| OpenAI 兼容 | OpenAI / DeepSeek / 通义 / 智谱 等，填对应 Base URL 与模型名 | 是 |
| 本地 Ollama | `http://localhost:11434/v1`，需本机已运行 Ollama | 否 |
| Anthropic Claude | 走 Messages API | 是 |

> 提示：把 Base URL 换成任意 OpenAI 兼容服务（如 DeepSeek `https://api.deepseek.com/v1`）即可对接。

## 说明与边界

- **不训练模型**：本项目是「自研前端 + 预训练模型接口 + 提示工程」。
- 人物卡通形象为**手工 SVG**（可替换）。
- 对话数据目前**不落库**，刷新页面即清空；人物配置存于 `data/figures.json`。
- 历史人物为**教学模拟**，允许展现立场与时代局限，不代表史实定论。

## 常见问题（Troubleshooting）

### 1. `SSL: CERTIFICATE_VERIFY_FAILED` / `unable to get local issuer certificate`
**原因**：python.org 版 Python 在 macOS 上没有安装根证书（默认 cafile 为空）。
程序现已**自动使用系统证书包** `/etc/ssl/cert.pem`，通常无需处理。
若仍报错：
- 运行一次 `/Applications/Python 3.14/Install Certificates.command`；或
- 启动时指定：`SSL_CERT_FILE=/etc/ssl/cert.pem python3 -m src.app.server`

### 2. `Base URL 必须以 http:// 或 https:// 开头`
Base URL 填错了，必须是完整网址：
- DeepSeek：`https://api.deepseek.com`（或 `https://api.deepseek.com/v1`）
- OpenAI：`https://api.openai.com/v1`
- 本地 Ollama：`http://localhost:11434/v1`

### 3. `HTTP 400` / `model not found`
模型名不对。常见正确值：
- DeepSeek：`deepseek-chat` 或 `deepseek-reasoner`
  （**不是**「DeepSeek v4 Flash」这类应用内模型名）
- OpenAI：官方模型 id，如 `gpt-4o-mini`
- Ollama：本机 `ollama list` 里的名字，如 `qwen2.5:7b`

### 4. `HTTP 401` / Authentication
API Key 无效，或该 Key 没有这个接口的权限。

### 5. 回复一直是模拟内容
检查对话框下方「API 接口」是否还停在「离线演示」。
